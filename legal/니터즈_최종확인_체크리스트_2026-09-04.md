- [ ] **위치기반서비스사업 신고 의무 여부**: 뜨개장터 직거래 위치 지도, 실험실 뜨개맵 두 기능 모두 "내 위치"를 서버로 전송하는 지점이 있어, 위치정보법 제9조상 신고 대상인지 확인.

## 2. 개발팀 확인 (6건)

- [ ] 실제 프로덕션 앱(iOS/AOS)에 **Mixpanel** SDK가 포함되어 있는지, GA(Firebase 포함) 외 다른 분석도구를 쓰는지.

- [ ] **DB/백엔드 아키텍처 최종 확인 (Supabase / Firebase 역할 분담)** — 개인정보처리방침 8·19절은 "Firebase Authentication은 인증, Google Cloud Functions·Firestore는 서버 처리와 인증용 임시정보 처리, Supabase는 계정·콘텐츠·파일·활동 정보의 저장"이라고 서술합니다. **Firebase와 Supabase를 같이 쓰는 구조라는 전제 자체가 맞는지, 그리고 아래 각 데이터가 실제로 어디에 저장되는지** 확인해 주세요. (참고: 지금 세션에 연결된 웹 프로토타입 저장소(`Yves-ds/knitters`)의 `package.json`에는 `@supabase/supabase-js`만 있고 Firebase 계열 패키지는 없었습니다 — 다만 이 저장소는 목업 데이터 기반 웹 프로토타입이라 실제 iOS/AOS 앱과 구성이 다를 수 있어 참고용입니다.)
  - [ ] 실제 앱 저장소의 의존성 파일 확인: Flutter면 `pubspec.yaml`, React Native면 `package.json`, 네이티브면 `Podfile`/`build.gradle`에서 `supabase-flutter`/`@supabase/supabase-js`류와 `firebase_core`/`firebase_auth`/`cloud_firestore`/`firebase_messaging`/`firebase_crashlytics`/`firebase_analytics`류가 각각 있는지, 그리고 실제로 import되어 쓰이고 있는지(설치만 되고 미사용인 패키지 제외).
  - [ ] 아래 데이터 유형별로 실제 저장 위치를 한 줄씩 답변: ① 로그인 인증/세션, ② 회원 프로필(닉네임·이메일 등), ③ 뜨개 기록(프로젝트·사진·도안), ④ 커뮤니티·뜨개장터 게시글, ⑤ 채팅 메시지, ⑥ 신고/앱 제보 데이터, ⑦ 코 수 세기 동의 사진·측정값.
  - [ ] Firestore가 정말 "인증용 임시정보"에만 쓰이는지, 아니면 다른 실사용 데이터도 저장하는지.
  - [ ] Supabase 프로젝트 대시보드에서 리전이 서울(ap-northeast-2)로 설정되어 있는지 — 방침의 "주요 데이터베이스는 대한민국 서울에서 저장·처리" 서술과 일치하는지 확인.
  - [ ] 확인 결과가 방침 서술과 다른 부분이 있다면 구체적으로 어떻게 다른지 회신.

- [ ] 가입 시 "마케팅 정보 수신 동의"와 마이>설정 "마케팅 앱 푸시 동의"가 **실제로 하나의 값으로 통합 구현**되어 있는지, 별도로 구현되어 있는지.
- [ ] **카카오 로그인이 카카오싱크 방식인지**, 전화번호 등 이름/사진/이메일 외 항목까지 추가로 수집되는지.
- [ ] 개인정보처리방침 보유기간표의 **실제 값 5곳** 확정 (계정정보, 콘텐츠, 대화·참가·출석 이력, 동의기록, 백업·로그 — 각 항목별 법적 최소기간 유무는 반영현황 문서 3번 표 참고).
- [ ] **[신규]** 커뮤니티 "뜨개구인"(테스터 모집) 게시판에 신청·승인·거절, 출석·불참 기록 같은 **구조화된 절차가 있는지**, 아니면 게시글+댓글/채팅으로 자유롭게 지원하는 방식인지. (함뜨 조항을 분리하면서 새로 확인이 필요해진 항목 — 자세한 내용은 개인정보처리방침 v2 초안 5절 참고)
