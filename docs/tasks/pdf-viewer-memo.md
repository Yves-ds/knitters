# [작업 요청] PDF 뷰어 메모 기능 추가

> 작성일: 2026-10-05
> 대상 화면: 기록 > 도안(PDF) 뷰어
> 관련 코드: `src/app/(main)/projects/[id]/edit/page.tsx` (`PatternSheet`, `PdfViewer`), `src/store/projectStore.ts`

---

## 1. 배경 및 목적

뜨개 중 도안 PDF를 보면서 "몇 단까지 떴는지", "사이즈 3 기준 코 수" 같은 메모를 바로 남기고 싶다는 니즈가 있다.
지금은 메모를 남기려면 PDF 뷰어를 닫고 기록 본문으로 돌아가야 한다.
**PDF 뷰어 우측 하단 플로팅 버튼 영역에 '메모' 버튼을 추가하고, 누르면 도안 위에 메모 입력창이 뜨도록** 한다.

## 3. 요구사항

### 3-1. 우측 하단 버튼에 메모 버튼 추가 — [기록_PDF 뷰어]

- 우측 하단 플로팅 버튼 스택의 **맨 위**에 메모 버튼을 추가한다.
  - 버튼 순서(위 → 아래): **메모** / 너비 맞춤(Fit Width) / 마크업(Markup) / 카운터(Bottom Counter)
- 버튼 스펙 (기존 플로팅 버튼과 동일)

| 항목 | 값 |
|---|---|
| 크기 | 44 × 44px, 원형 (`rounded-full`) |
| 배경 | `#FFFFFF`, opacity 90% |
| 그림자 | `0 4px 20px 1px rgba(23,23,23,0.04)` + `0 0 30px rgba(23,23,23,0.1)` |
| 아이콘 | `Icon/Normal/Memo` 24 × 24px, 색상 `#5E5E5E` (Semantic/Label/Neutral) — Figma에서 SVG export 후 인라인 SVG로 사용 |
| 버튼 간격 | 12px (세로 스택) |
| 위치 | 화면 우측 16px, 스택 하단이 화면 하단에서 40px |

### 3-2. 메모 버튼 탭 → 메모 입력창 표시 — [기록_PDF 뷰어 (메모)]

- 메모 버튼을 누르면 **메모 버튼 자리에 메모 입력창이 펼쳐진다.**
  - 메모 상태에서는 메모 버튼이 사라지고, 나머지 3개 버튼(너비 맞춤 / 마크업 / 카운터)만 남는다.
  - 입력창은 남은 버튼 스택 바로 위(간격 약 12px)에, 오른쪽 끝을 버튼과 맞춰 배치한다.
- 입력창 스펙

| 항목 | 값 |
|---|---|
| 크기 | 279 × 200px (393px 기준 화면, 좌 98px / 우 16px 여백) |
| 배경 | `#F6F6F6` (Semantic/Background/Input) |
| 모서리 | 20px |
| 그림자 | `0 4px 20px 1px rgba(23,23,23,0.04)` |
| 안쪽 여백 | 좌우 16px, 상하 10px |
| 텍스트 | Pretendard Regular 12px / line-height 20px, 입력 텍스트 색 `#5E5E5E` |
| 플레이스홀더 | "메모를 입력해주세요." / 색상 `#8A8A8A` (Semantic/Label/Alternative) |

- 동작
  - 입력창은 여러 줄 입력이 가능한 `textarea`로 구현한다. 내용이 높이를 넘으면 입력창 내부에서 스크롤된다.
  - 열릴 때 자동으로 포커스를 주고 키보드를 띄운다.
  - 입력창 **바깥 영역(PDF 등)을 탭하면 입력창이 닫히고** 메모 버튼이 다시 나타난다.
  - 키보드가 올라와도 입력창이 키보드에 가려지지 않아야 한다 (`visualViewport` 기준으로 위치 보정).
  - 열기/닫기 시 짧은 fade + scale 애니메이션 (기존 시트의 `cubic-bezier(0.32, 0.72, 0, 1)` 이징 재사용).
  - 메모 입력창이 열려 있어도 PDF 스크롤/핀치 줌은 막지 않는다 (바깥 탭 = 닫기만 처리).

### 3-3. 메모 저장

- 메모는 **프로젝트(기록) 단위로 1개**를 저장한다. (페이지별 메모는 이번 범위 아님)
- `Project` 타입에 필드 추가: `pdfMemo?: string`
- 입력 중 debounce(약 500ms)로 `updateProject(id, { pdfMemo })` 호출 → zustand `persist`로 로컬 저장.
- PDF 뷰어를 다시 열면 이전 메모가 그대로 보여야 한다.
- 메모가 저장되어 있으면 메모 버튼에 상태 표시(예: 아이콘을 Primary `#F72E00`으로)하는 것을 권장 — 디자인 확인 필요 (아래 6번 참고).
- PDF를 삭제해도 메모는 유지한다. (PDF 변경/삭제와 독립)

## 4. 구현 참고 (현재 코드 상태)

- 현재 PDF 뷰어는 `PatternSheet` 안에서 `PdfViewer`(PDF.js CDN, 캔버스 세로 나열)로만 구성되어 있고, **우측 하단 플로팅 버튼 스택이 아직 없다.**
  - 이번 작업에서 플로팅 버튼 스택 컨테이너를 만들고 **메모 버튼만 실제 동작**하도록 구현한다.
  - 너비 맞춤 / 마크업 / 카운터 버튼은 이번 범위가 아니다. 이미 구현되어 있지 않다면 별도 작업으로 분리한다 (자리만 잡아두는 것은 PM 확인 후 결정).
- 상단 GNB(닫기 / 페이지 이동 `1 / 7` / 북마크)와 줌 배율 표시(`100%`)도 이번 범위가 아니다.
- 메모 컴포넌트는 `PdfMemo` 같은 별도 컴포넌트로 분리하고, `PatternSheet`에 `memo`, `onMemoChange` props를 추가해 상위(`edit/page.tsx`)의 상태와 연결한다. (`pdfUrl` / `onPdfChange` 패턴과 동일하게)
- 스타일은 기존 코드처럼 Tailwind arbitrary value(`text-[12px]`, `bg-[#F6F6F6]` 등)를 사용하고, `DESIGN_SYSTEM.md`의 컬러/타이포 규칙을 따른다.
- PDF 시트가 닫히면(`isOpen === false`) 메모 입력창도 닫힌 상태로 초기화한다.

## 5. 완료 조건 (Acceptance Criteria)

- [ ] PDF가 등록된 상태에서 뷰어를 열면 우측 하단에 메모 버튼이 Figma와 동일한 위치·모양으로 보인다.
- [ ] 메모 버튼을 누르면 메모 버튼이 사라지고 279 × 200 메모 입력창이 나타나며 바로 입력할 수 있다.
- [ ] 비어 있을 때 "메모를 입력해주세요." 플레이스홀더가 보인다.
- [ ] 입력창 바깥을 탭하면 입력창이 닫히고 메모 버튼이 다시 보인다.
- [ ] 메모를 입력하고 뷰어를 닫았다가 다시 열거나, 앱을 새로고침해도 메모가 유지된다.
- [ ] iOS Safari / Android Chrome에서 키보드가 올라와도 입력창이 가려지지 않는다.
- [ ] 메모 입력창이 열린 상태에서도 PDF 스크롤과 핀치 줌이 정상 동작한다.
- [ ] `npm run build`(타입 체크 포함)가 통과한다.

## 6. 확인 필요 사항 (디자인/기획)

1. **닫기 방법**: 디자인에 닫기 버튼이 없어 "바깥 탭 시 닫힘"으로 가정함. 확인 필요.
2. **메모 저장 여부 표시**: 메모가 있을 때 메모 버튼에 표시(색상/뱃지)가 필요한지.
3. **메모 단위**: 프로젝트당 1개로 가정함. 페이지별 메모가 필요한지.
4. **글자 수 제한**: 제한이 있다면 몇 자인지 (가정: 제한 없음).
5. Figma 메모 입력창 레이어 안에 `Chevron Right` 아이콘(x=329)이 입력창 폭(279) 밖에 있어 화면에 보이지 않음 → 사용하지 않는 레이어로 판단하고 구현하지 않음. 의도된 요소라면 알려주세요.
